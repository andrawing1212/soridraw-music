# SORIDRAW Codex 사용량 절약 지침

> 목적: 어려운 작업은 충분히 깊게 검토하되, 같은 저장소/같은 원인을 반복 분석해서 Codex 사용량을 낭비하지 않는다.

## 기본 추천
- 현재 대형 백엔드 작업: **GPT-6 Astra Medium** 권장.
- Light: 작은 UI/CSS/문구/단순 파일 수정.
- Medium: 여러 파일, Cloudflare/Firebase, 캐시/동기화/비용 최적화의 기본.
- 더 높은 추론 단계: 데이터 손실 위험, migration, 복잡한 동시성/복합 장애처럼 Medium으로 안전하게 결론을 못 낼 때만 사용한다.
- 높은 단계가 필요하다고 판단되면 스스로 무한히 계속하지 말고 **현재 근거와 막힌 지점을 보고하고 중단**한다.

## 짧은 Codex 명령이 기본 (2026-10-27 디렉터 확정)

- **작업 지시는 짧게:** 목표 1개, 정확한 변경 범위, 금지 사항, 합격·저장 기준만 쓴다. 보통 3~6문장으로 충분하다. 안전상 꼭 필요한 위험 조건만 덧붙인다.
- **기존 문서 재사용:** `AGENTS.md`와 현재 작업 문서를 읽도록 지정하고 규칙 전문·과거 기록·기존 코드를 프롬프트에 다시 붙이지 않는다.
- **동일 작업 재지시 금지:** 기존 확정 명령을 번복하거나 장문·단문 버전을 반복하지 않는다. 중단된 작업은 보존된 커밋과 마지막 작업 지점만 이어간다.
- **실제 비용 절약:** 핵심 수정과 원격 GitHub 보존을 우선하고, 이미 통과한 검사·중복 분석·형식적 절차는 반복하지 않는다. 저위험 필수 정리는 즉시 수행한다.
- **코드 정리는 예외:** 다음 개발과 충돌할 구체적 근거가 있을 때만 최소 범위를 제안하고 승인을 받는다. 파일이 길다는 이유로 전면 재작성하지 않는다.

## 사용량 절약 규칙
1. 시작 시 `AGENTS.md` → `CURRENT_RELEASE_STATE.md` → `NEXT_CODEX_TASK.md`를 먼저 읽고, 필요한 파일만 추적한다.
2. `WORK_LOG.md` 전체나 저장소 전체를 매번 다시 읽지 않는다. 현재 원인 확인에 필요한 경우만 부분 조회한다.
3. 이미 확인된 구조를 처음부터 재설계하지 않는다. 현재 task의 문제와 합격선만 해결한다.
4. 전체 저장소 검색은 최초 소유 파일/호출 경로 확인용 1회 수준으로 제한하고 이후에는 좁은 검색을 사용한다.
5. 작은 수정마다 전체 TypeScript/Build를 반복하지 않는다. 수정 중에는 관련 파일/검증만 실행하고, 최종 후보에서 전체 TypeScript/Build/필수 Test를 실행한다.
6. 기존 verifier가 있으면 재사용한다. 같은 목적의 진단 스크립트/패치 파일을 계속 추가하지 않는다.
7. 임시 도구가 필요하면 최소화하고, 최종 코드에 불필요한 임시 실행 경로를 남기지 않는다.
8. 같은 접근이 반복 실패하면 무작정 재시도하지 않는다. 실패 로그와 원인을 고정하고 다른 접근의 근거가 없으면 중단/보고한다.
9. 이번 task 범위를 넘어 FCM/WebSocket/새 외부 서비스 같은 새 인프라를 추가하지 않는다. 필요성이 보이면 제안만 남긴다.
10. 배포는 하지 않는다. 구현 → 테스트 → commit까지만 수행한다.

## 디렉터 요구 — 시간 소진 전 작업물 안전 저장 (2026-10-27)

- 작업을 시작할 때 `DOCS/DIRECTOR_WORK_RULES_AND_DAILY_ROUTINE.md`의 **합의 기능 전체/누락 금지/매 작업 체크리스트**를 따른다.
- 분석·구현 중 복구 가능한 안전 지점에서 GitHub Draft/WIP commit/push를 **먼저 보존**한다. 최종 검사 PASS 전에 저장했다면 미검증을 명시한다.
- Codex 시간·사용량이 제한되면 새 분석·무한 재검증보다 기존 수정의 **원격 저장과 SHA 확인**을 우선한다. 사용량 자체를 볼 수 없으면 미확인이라고 보고한다.
- push 권한/연결 문제 발생 시 추가 기능 구현을 멈추고 저장 실패 원인 및 로컬 커밋 SHA/파일 목록/복구 경로를 기록한다. push 없이 'GitHub 완료'라고 표현하지 않는다.
- 한 작업에 확정 명령문 하나를 유지한다. 이미 PASS된 검사를 같은 소스에 반복하지 않고, Work는 실제 push된 정확한 SHA에서 문제 부분을 중심으로 검증한다.
- 계약된 기능 중 일부를 빼야 할 경우에는 사용자 승인 없이 임의로 생략하지 않는다.

## 완료 조건
사용량을 아끼기 위해 검증을 생략하지 않는다. 마지막 후보에서는 반드시 task에 적힌 TypeScript / Build / 관련 Test / 비용 회귀 검증을 수행한다.
