# SORIDRAW 작업·배포 고정 지침

> 새 채팅/새 작업자는 저장소를 불러오면 이 문서를 먼저 확인한다.

## 작업 기준
- `preview` = 큰 수정/안전작업/프리뷰 검증
- `main` = 테스트앱 기준
- Firebase Production은 사용자가 명확히 `정식배포` 승인 전 절대 배포하지 않는다.

## 현재 단계
**3/7 뮤직노트·라이브러리 페이지네이션 정상화 — 실사용 검증 실패 후 재설계 중.**

## Stage 3 금지사항
- 전체 favorites/tracks 일괄 읽기 금지
- 2,000건 compatibility scan 금지
- 캐시를 전부 소진한 뒤 서버 다음 페이지를 읽는 구조 금지
- 실제 총량과 다른 임의의 `20개 더보기` 표시 금지
- 가만히 있어도 Firestore read/write가 계속 증가하는 구조 금지

## Stage 3 재설계 원칙
- 캐시는 최초 화면의 빠른 표시만 담당한다.
- 실제 목록 기준은 서버의 20개 단위 페이지 체인 하나만 사용한다.
- 더보기 클릭은 캐시 소진을 기다리지 않고 서버 다음 페이지를 요청한다.
- 남은 곡 수는 권위 있는 서버 총량 기준으로만 표시한다.
- 정확한 총량이 없으면 숫자를 추정해서 표시하지 않는다.
- 기존 사용자 데이터 삭제/덮어쓰기/백필 없이 해결한다.
- Explore/Hosting/Auth/Functions/Rules는 Stage 3에서 건드리지 않는다.

## 진행상황 보고 — 절대 생략 금지
모든 작업 중/후 보고 맨 위에 반드시 표시한다.
- 전체 목표
- 현재 단계 N/7
- 현재 단계 진척도 %
- 전체 7단계 진척도
- 이번에 수정한 것
- 다음 작업
- Preview / Test / Production 배포 상태

## 영구 작업 메모 — 모든 작업에 적용
- 현재 상태 요약: `DOCS/DEPLOYMENT_PROGRESS.md`
- 누적 작업 일지: `DOCS/WORK_LOG.md`
- 모든 진단, 설계 결정, 수정, 테스트, 실패, 롤백, 배포 결과를 `WORK_LOG.md`에 append한다.
- 새 채팅은 `AGENTS.md` → `WORKFLOW_GUARDRAILS.md` → `DEPLOYMENT_PROGRESS.md` → `WORK_LOG.md` 순서로 확인한다.

## 데이터 안전
Firestore/Auth/Functions 저장 구조나 읽기 방식이 바뀌면 기존 사용자 데이터 호환성을 먼저 확인한다.
기존 데이터를 못 읽거나 덮어쓸 가능성이 있으면 배포하지 않는다.
데이터 삭제/덮어쓰기/백필은 별도 승인 없이 실행하지 않는다.

## UI 고정
앱의 버튼/창에 외곽선(테두리 선)을 새로 넣지 않는다.
기존 디자인·반응형 동작은 요청 없는 한 변경하지 않는다.
