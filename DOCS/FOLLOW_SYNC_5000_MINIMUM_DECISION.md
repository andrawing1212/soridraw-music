## 실제 확인한 동작과 부족한 부분
- 정상 팔로우 버튼은 `ExplorePage.tsx`에서 `immediate:true`로 **즉시 서버 저장을 요청**한다. 비즉시 복구 경로의 타이머를 줄여도 B 클릭 후 A로 자동 전달되는 문제는 해결되지 않는다.
- D1 정본 변경이 확정되기 전에는 A의 수나 목록을 확정된 사실처럼 표시하면 안 된다.
- `userSync/{B}/exploreFollow`는 **B 계정의 PC↔모바일** 신호일 뿐, 별도 사용자 A의 팔로워 자동 갱신 신호가 아니다.
- 기존 APP527의 포커스·탭 이동 불필요한 조회 제거 및 APP528의 **120초 팔로워 목록 캐시**를 유지한다. A의 열린 프로필에서만 소유자 신호 구독, 목록이 열려 있으면 해당 목록만 좁게 무효화/조회한다.
- 지향 UX: B 즉시 낙관적 반영, 서버 확정 후 A의 숫자 자동 동기화, 반대 클릭·중복·재시도·오프라인 복귀·구형 앱에도 마지막 정본 일치. 10–20초는 실제 브라우저에서 검증할 목표이지 지금 보장할 수치는 아니다.
